# container.json reference

Copy `container.example.json` to `container.json` and edit it. `container.example.json` holds the
everyday keys and `container.sources-example.json` the optional data sources (merge the lines you
want into your file); every key either one carries, and every other key the code reads, is below.
The file is chosen in this order:

1. `--config PATH`, then `$CONTAINER_CONFIG`.
2. Without `--root` (or `$CONTAINER_ROOT`): `container.json` next to `config.py`.
3. With `--root ROOT`: `ROOT/.container-map/container.json` if it exists. Otherwise the tool's own
   `container.json` is reused only when its `work_root` resolves to the same folder as `ROOT`.
   If neither applies, no file is read and the built-in defaults in `config.py` are used.

`container-map thread …` with none of `--config`, `--root`, `$CONTAINER_CONFIG` and
`$CONTAINER_ROOT` adds a step before the tool's own file: it looks for the nearest
`.container-map/container.json` (or, for a map served without `init`, `.container-map/tasks` or
`run`) at or above the folder the thread works on (its TARGET for `thread new`, then the current
folder; the current folder for every other subcommand) and uses it as if that folder had been given
as `--root`. A `container.json` that cannot be parsed is still the
one found: `config.py` warns and uses the defaults, and `container-map doctor` says it is not ready.

The bridge's credentials file is not a config key: it is `ROOT/.container-map/run/bridge-<port>.json`
(see [CLI.md](CLI.md), which also says where it goes when that folder cannot be written), or
wherever `--live-file` / `$BRIDGE_LIVE_PATH` says.

Rules that apply to every key:

- A key whose JSON type differs from its default's type is ignored (the default stays); `t3_state` may also be a list of strings.
- Keys that are not in the defaults are ignored, including keys starting with `_` (use those as comments).
- Nothing is ignored silently: `container-map doctor` prints an `ignored` row, with the reason, for each key of the file that was dropped (an unknown key, a value of the wrong type); keys starting with `_` are not listed. `config.load()` keeps the same list as `_dropped`, and `container-map config` prints it.
- `~` at the start of a path is expanded for the path keys, `extra_areas` values, `script_dirs` folders, `file_roots`, `planets` paths, `t3_state` and the `today` path keys. An empty path means "not configured" for the optional file sources (`digest`, `fleet`, `relay_dir`, `reads_jsonl`, `tags_md`, `tasks_json`, `dispatch_dir`, `runners_json`, `audit_json`, `pilot_log`): that source is not drawn, never invented. For `tasks_dir`, `worktrees_dir`, `workflows_dir`, `history_jsonl`, `verbs_dir`, `out`, `rounds_json`, `synced_dir`, `task_runs_json` and `rulings_json` an empty path selects a default location, and for `crontab_file` it runs `crontab -l`; the per-key lines give each default.
- `--root DIR` (or `$CONTAINER_ROOT`) overrides `work_root`, and sets `name` to the folder name in capitals if `name` was left at its default. `$CONTAINER_OUT` overrides `out`.

Nothing is strictly required: with no file at all the map renders a generic workspace. These two are
the ones you will usually set.

## Usually set

- `name` — string, default `"CONTAINER"`. The label of the star (this machine). With `--root` and no name set, the root folder's name in capitals is used.
- `work_root` — string path, default `"~/work"`. Your workspace; its top-level subfolders are the planets (areas). The file preview, task folders and history file also live under it.

## Optional

Generic sources: they work on any machine and are skipped when absent.

- `version` — number, default `1`. Informational: nothing reads it. The example files carry `1`.
- `extra_areas` — object `{label: path}`, default `{}`. More planets outside `work_root`, e.g. `{"notes": "~/Documents/notes"}`. Threads, doors and the file preview all reach them.
- `private` — list of folder names or paths, default `[]`. A paired phone sees only the folder's name and counts, with no child folders, file names or file lists. Dot-folders always have this protection. A name such as `"vault"` matches folders with that name; a path such as `"notes/personal"` is relative to `work_root`, and absolute paths or paths starting with `~/` also work. The local map keeps its file lists. This controls the phone's map payload; it does not change local filesystem permissions. Conversation groups have their own `private` setting under `constellations`.
- `script_dirs` — object `{folder: planet name}`, default `{}`. Folders of scripts that belong to a planet: a cron line whose script lives in the folder, or a running process whose command line names it, is homed to that planet (the name must be one the map draws, a `planets` name, `extra_areas` label or top-level folder). `{"~/bin": "scripts"}` homes everything in `~/bin` to the planet `scripts`. Without it, a task is homed only by the paths it names inside a planet.
- `planets` — list of `{name, path, kind, desc, tag}`, default `[]`. Your own planet list, in order. `kind` is one of code, knowledge, shared, bus, config, reference, archive. `[]` means every top-level folder of `work_root`. A planet inside another is cut out of the parent's count.
- `tmux_session` — string, default `""`. The tmux session whose windows are the seats. `""` uses the session you are running in (if any); `"none"` means no seats.
- `hangar_slots` — whole number, default `6`. How many berths the hangar plate counts: the map's agent seats and ships are counted against it (`BERTHS used/slots`), with a warning once the count is over. It is a display only: nothing is stopped, closed or killed when there are more. A whole number from 1 to 99; anything else is ignored (the default stays).
- `processes` — boolean, default `true`. Read the process table and attach running processes to the areas they work in.
- `crontab_file` — string path, default `""`. Read cron lines from this file; `""` runs `crontab -l`.
- `cron_syslog_file` — string path, default `"/var/log/syslog"`. The system log read to learn when each cron line of your crontab last fired (its read position is cached in `ROOT/.container-map/cron-syslog.json`). `""` turns it off, and the map then uses the cron lines' own log files' modification times, as it also does when this log is missing or unreadable. The rotated `<file>.1` is read too.
- `file_roots` — list of paths, default `[]`. Extra folders that are read-only to the map: the file preview and the `decision_scan` walk may reach them (open-in-editor stays within the task roots), on top of `work_root`, `extra_areas` and the planets. Nothing runs there: threads, doors, verbs and board hand-offs are checked against `work_root`, `extra_areas` and the planets only, and a folder that is only in `file_roots` is not drawn.
- `out` — string path, default `""`. Where the rendered HTML goes; `""` means `game.html` next to the tool (`ROOT/.container-map/game.html` with `--root`).
- `constellations` — list, default `[]`. Optional conversation groups, in order: `[{"name":"Writing", "key":"writing", "keywords":["draft"], "private":false}]`. A scan finding can supply a group name too. With neither config nor findings there are no groups or empty wedges. `key` maps a scan's short key to the displayed name; `keywords` match conversation titles and paths; `fallback:true` receives unmatched conversations. A `private:true` group exposes only a count on phones, including hiding folded children and their other map aliases.
- `constellation_rules` — list of group names, default `[]`. Optional keyword matching order; otherwise the order in `constellations` wins. The first match wins.
- `lane_planets` — object, default `{}`. Optional conversation group words mapped to folder names, for example `{"writing":"notes"}`. Exact folder names already match without this.
- `demo` — boolean, default `false`. Marks the page as a generated demo workspace, not a real machine. Set by `demo.py`; leave it off.
- `runners` — object `{name: spec}`, default `{}`. Agents that can take tasks and board hand-offs. A runner's name (its key) must be lowercase letters, digits and hyphens, start with a letter or digit and be at most 32 characters (`[a-z0-9][a-z0-9-]{0,31}`); a runner with any other name is dropped without a message. Spec keys: `cmd` (argv list; `{text}` in an argument is replaced by the prompt, otherwise it goes on stdin), `followup_cmd` (argv for a reply; `{session}` is the agent's session id), `check_cmd` (read-only argv used to review work), `max_minutes` (number, default 30, up to 1440), `check_minutes` (number above 0, up to 1440: the time cap of a check run; default the smaller of `max_minutes` and 10), `desc`, `label`, `role` (`work`, `check` or `both`; a runner with no read-only command cannot review), `models` (list of names or `{name, label, desc, args, env}`), `default_model` (name from `models`, default the first), and for board hand-offs `cwd` (`item` or `tool`) and `report_dir`. Malformed runners are dropped.
- `agent_verify` — boolean, default `false`. Whether an agent (the bearer token, `POST /agent/task`) may set a thread's `verify`, `retries` and `setup` lines. They are shell lines the bridge runs as you, so by default only the page can: an agent's request that carries any of them is a 400. The page's own `POST /task` is never gated.
- `theme` — string, default `"classic"`. The map's theme and texture pack: the name of a file in `themes/` (`classic` is the original look; also `earthen`, `blueprint`, `synthwave`, `phosphor`, `tactical` (a military operations console drawn as hairline vectors)). `V` in the page cycles the packs and the browser's own choice wins over this default. The ids this tool used before it renamed two themes still work in a config and in a browser's saved choice.
- `skin` — string, default `"neutral"`. The map's skin: the name of a file in `skins/` (or in `skins_dir`). A theme is colours and tiles and the page cycles it; a skin is the craft (the pilot ship and its boost variant, the carrier, the raiders that stand for problems), the words on the plates (the carrier's label, the banner when a thread merges, the word before `-CLASS` on the most troubled planet), the wingmate's default name and its portrait. It is fixed per map: the page does not switch it. A skin that is missing or broken falls back to `neutral` with a warning when the page is rendered. The file shape is written at the top of `themepacks.py`: `names` (the carrier's plate, the merge banner at most 16 characters, the word before `-CLASS`, the wingmate's name), `sprites` (`pilot`, `carrier` and `raider`, optionally `pilot_boost`; the warp gate stays a theme's), an optional `sprite_palette` for letters of your own (not `a` or `e`, which are the page's status colour and engine; the mono palette is fixed, so a skin's own letters do not show under it) and an optional `portrait`. `python3 -m unittest test_game` validates the shipped skin; one of your own is validated when the page is rendered. A theme file written for an earlier version that names the planet surface `blight` by its former name is still read, with a warning.
- `skins_dir` — string path, default `""`. Your own skins: a folder of `<name>.json` looked in before the tool's own `skins/`, so a skin there wins over a shipped one of the same name.
- `home_planet` — string, default `""`. The planet name carrying the home ring; empty means no home ring. `wingmate.home_planet` overrides it when supplied.
- `wingmate` — object, default `{}`. The map's helper (default name: the skin's, `Scout` in the neutral skin). Keys: `name` (default the skin's name, at most 24 characters), `cmd` (argv list that reads the question on stdin), `env` (extra environment, names `A-Z0-9_`, laid over the clean environment an agent gets: no `BRIDGE_*` or `CONTAINER_*` variable of the map, no token path), `max_seconds` (5 to 600, default 60), `models` (up to 8 of `{name, label, family, env?, args?, cmd?}`: `name` is letters, digits, `.`, `_` or `-` up to 32 characters, `family` is claude, openai, google, xai or other; a model's `env` is merged over the base `env`, its `args` are appended to the base command, its `cmd` replaces the base command), `default` (the `models` name asked when none is picked; else the first), `model` (a label only, for a config that has a `cmd` and no `models`), `off` (true with no `cmd` turns it off), `mothership` (name of the tmux window drawn as the carrier, the ship task ships launch from; default `"hub"`) and `home_planet` (the planet that carries the gold ring; default the top-level `home_planet`, else none). `{}` uses `claude -p` if `claude` is on PATH, with the models haiku, sonnet and opus and haiku as the default, plus Codex (OpenAI) through `codex exec` and Gemini when `codex` or `gemini` is on PATH; either of those alone is enough. With none of the three the map only explains itself. `container-map init` writes that list into your config.
- `tasks_dir` — string path, default `""`. One folder of receipts per task; `""` means `work_root/.container-map/tasks`.
- `tasks_dir` — string path, default `""`. One folder of receipts per task; `""` means `work_root/.container-map/tasks`. Every process that uses the same folder (the map, `cli.py thread`) shares its `.store.lock`, which keeps them from both taking the last free place; it must be on a filesystem that supports `flock` (a local disk; Windows is not supported).
- `worktrees_dir` — string path, default `""`. Where a new thread's git worktree goes (`<worktrees_dir>/<thread id>`); `""` means `<tasks_dir>-worktrees`, beside the receipts folder and never inside it (so the parent of `tasks_dir` must be writable by you; if it is not, for example `tasks_dir` is `/mnt/data`, set `worktrees_dir` to a folder you can write, or a worktree thread fails with `could not make the worktrees folder`), so an agent's `../task.json` and `../events.jsonl` are not the thread's receipts. It must be a folder of its own and not inside `tasks_dir`; a thread cannot be aimed at it. Threads made before this key keep their worktree inside their receipts folder and keep working; to move the folder, close open threads first (a thread whose worktree is not where the setting says is refused as altered). Trust model: agents run as your user, so this stops accidents and casual forgery (a stray `../events.jsonl`, an agent that rewrites its own verify line), not a determined agent that finds the receipts by their path; a thread also refuses to act on a record changed after it started.
- `workflows_dir` — string path, default `""`. One folder per workflow (a few steps an agent puts on the map and updates live, each at the folder it works in); `""` means `work_root/.container-map/workflows`. Nothing in it is deleted: closed workflows move to an attic.
- `workflow_launches_per_day` — whole number, default `40`. How many agent tasks the workflows agents started may launch together since local midnight (every seat shares one subscription quota); past it, a ready task step waits for tomorrow or your Retry and says so. Workflows you start yourself, and steps you retry, are not counted.
- `workflow_artifact_mb` — whole number, default `32`. How many MB of its steps' output files one workflow may keep as snapshots (8 MB a file at most).
- `three_inline` — boolean, default `false`. The 3D view's code (three.js and the map's own 3D modules) is served once from a cached `/vendor/` address; `true` writes it into the page itself, so a saved page is one file that works offline.
- `merge_skip` — list of gitignore-style patterns, default `["__pycache__/", "*.pyc", ".pytest_cache/", ".mypy_cache/", "node_modules/", ".DS_Store", ".mimocode/", "*.egg-info/", ".venv/"]`. When a merge or a set-aside commits what the agent left uncommitted, untracked files these patterns name (and `.gitignore` does not already cover) are left out, so a repo without a `.gitignore` does not get build junk on the branch. A file git already tracks is always committed. The merge receipt (`skipped`) and the message name what was left out. What is then removed with the worktree: untracked files the *built-in* list above names (they are known junk, `.mimocode/` included) go with it, and the message says so. Files only your own list names (a `*.log`, a `dist/`) are never deleted: the worktree is kept and moves to `<worktrees_dir>/<id>.retired-<stamp>`, so put a folder you do not mind losing in `.gitignore` instead. If git cannot list the untracked files, nothing is committed and the merge or set-aside fails with a 502 (the skip list is never guessed at). Your list replaces the default; `[]` commits everything, as before. Malformed entries (not a string, empty, over 200 characters, a control character) are dropped.
- `merge_requires_check` — boolean, default `false`. When `true`, a thread with no fresh PASS from a check run (none, an outdated one, or only checks that crashed or are still running; a recheck that crashes, is stopped or is still running does not take back an earlier PASS that is still fresh, see `last_verdict`) gets the merge blocker `no independent check`: a merge needs the force flag until another agent has passed the work after its last change. A fresh FAIL is named as itself. Off, a passing `verify` line is enough, which is the thread's own test and not proof of correctness; every thread's summary carries `evidence` (`none`, `verified`, `checked` or `verified and checked`) either way.
- `ui_lock` — boolean, default `false`. For a computer other people also log in to. Off: any process on this computer can open the page (`GET /`) and get your session. On: a request without a session gets a plain page that says the map is locked (403), and the page opens only through the private link `container-map serve` prints (`/?k=<launch key>`; the key is random at every start, kept in the bridge's mode-600 live file and never logged, and the redirect that follows drops it from the address bar). The agent API, MCP and the phone listener are not affected. `serve --lock` and `install --lock` turn it on without editing this file; `container-map link` prints the link of a running locked map. See README, "Who can open your map".
- `remote` — object, default `{}`. Phone access, off while empty. Keys: `listen` (required: one IP address of this machine, not `0.0.0.0`; behind a reverse proxy `127.0.0.1`), `public_origin` (required: `https://<host>` or `http://<tailnet ip or name>:<port>`, no path; the listener answers only a `Host` that equals its authority and only a mutation whose `Origin` equals it), `port` (whole number, default the bridge port + 1, never the bridge port), `allow_http` (boolean, default `false`) and `trusted_proxy` (list of IP addresses, default `[]`: the reverse proxies in front of the listener, such as `["127.0.0.1"]`; for a connection that comes from one of them the client address, which the pairing limit, the lockout and the audit are kept by, is the last hop of `X-Forwarded-For`, so each phone has its own and not the proxy's shared one; a connection from any other address never has its header believed, and a malformed or missing header leaves the proxy's address; from such a connection a single clean `Tailscale-User-Login` header is also copied into the audit rows as `tailscale_user_login`, a record, never a gate). An `http://` `public_origin` is accepted only when `listen` is in `100.64.0.0/10` (Tailscale, encrypted) or `allow_http` is `true`. A block with an unknown key, or any other mistake, is refused: the reason is printed, logged and shown by `container-map pair`, and the loopback bridge runs without the listener. A block that is fine but cannot bind yet (the address is not on this machine yet, the port is held) is not refused: the listener is tried again every 30 seconds until it opens, and each kind of failure is printed and logged once. Paired devices live in `remote-sessions.json` and refused requests in `remote-audit.log`, both beside the tasks folder. See README, "Use it from your phone".
- `worktree_setup` — object `{repo path or "*": shell line}`, default `{}`. One shell line a new thread runs in its fresh git worktree before its agent's first run (`{"*": "npm ci"}`); on a follow-up only until one setup has passed (a setup that failed or timed out runs again before the agent), never on a check, and never for a thread that works in place. A thread is looked up by its repo's path first, then `"*"`; a setup line set on the thread itself wins (only the page may set it, unless `agent_verify` is on). A line must be one line of at most 400 characters with no control characters (others are dropped), and it is stopped after 600 seconds. A non-zero exit ends the run with exit code 125 ("setup failed") before any agent starts.
- `task_scope` — boolean, default `true`. Run each task's supervisor in its own `systemd --user` scope so restarting the map does not kill a running task.
- `tick_seconds` — whole number, default `10`. The bridge's own clock for the oracle loop: every N seconds a thread whose verify failed and has retries left goes back to its agent, with or without a page open (reading the thread list does the same). `0` turns the clock off, and retries then wait for a read of the list. Anything but a whole number (`2.5` included) is ignored and `10` stays.
- `no_ai_trailers` — boolean, default `false`. Tell agents not to sign commits, and refuse to merge a task branch whose commits carry `Co-Authored-By`.
- `detect_runners` — boolean, default `true`. When `runners` is empty, offer agent CLIs found on PATH (claude, codex, gemini, aider).
- `history_jsonl` — string path, default `""`. Hourly per-root snapshot (age, stale crons, trouble) used to show what is getting worse; `""` means `work_root/.container-map/history.jsonl`.
- `verbs_dir` — string path, default `""`. Verb manifests (`<name>.json`) offered on matching units; `""` means `ROOT/.container-map/verbs` with `--root`, else the tool's own `verbs/`.
- `areas_json`, `seats_json` — string paths, default `""`. Per-area kinds/workers and tmux seat policies (talk commands, machines). `""` looks next to the config, then in `ROOT/.container-map/`, then (without `--root`) next to the tool.
- `t3_remote` — optional SSH metadata sources; default `[]`. See Remote T3 metadata below.
- `t3_state`, `agent_processes`, `ship_machines` — T3 metadata SQLite (read-only; path or list of paths, default `""`), background agent processes drawn as ships (boolean, default `false`), and machine names for snapshot ships under `synced_dir` (list, default `[]`). With `agent_processes` off the page carries no agent run of any other process: no ship, an empty in-flight list, and no process row for a command line that names an agent (`claude -p`, `codex exec`, `muse exec`, `grok --sandbox`, `ralph`, `dispatch`, a `claude`, `claude-worker`, `codex` or `threads` command), so its pid, its tool and its prompt stay off the page. The `processes` key still homes the other processes (their pids and command lines) to the planet whose path they name; turn that off too to read no process table at all.
- `t3_link` — string, default `""`. The web address of the T3 Code server whose database `t3_state` names, such as `https://host:port` (a path after the host is kept, a trailing `/` is dropped). With it, a T3 thread gets an "open in T3" link to `<t3_link>/bridge?focus=<environment id>:<thread id>` when that database has its `environment-id` file beside it; `""` means no link. A thread that two `t3_state` databases both list is drawn from the first one listed, with that database's state and only that database's link: a copy's link is never put on another database's thread, since settling the copy would not change what the map shows (list the copy first to make it the one in use). Only an `http://` or `https://` address that starts with its host (no `user@`), has a number port if any, and has no space, quote, `?` or `#` is kept; anything else is ignored. The map only links: it never writes to T3.

## The Today screen

Today is the first screen. It lists, in plain words: what is on your to-do list, what waits on you, what your agents are doing now, what got done today, and what each folder is for. Every line is read from a file or a git folder when the page is built; a source you do not name is not drawn, and one that cannot be read says so on the page instead of showing a blank.

Two sources are generic and work on any machine. Name them in the `today` object of `container.json`:

- **todo_md** — path to any markdown checklist. `- [ ] item` lines are open and `- [x] item` lines are done; the open ones (up to 12) and the last three done ones are listed under Do today. Other lines are ignored.
- **git_dirs** — list of git folders. The commits made in them since midnight are listed under Done today, newest first, with the commit's subject and time.

Threads you start from the map need no setting: they show under Running now, with their state.

```json
"today": {"todo_md": "~/notes/todo.md", "git_dirs": ["~/code/app", "~/code/site"]}
```

### Readers for other formats

If you already keep records in one of these shapes, name the file and Today reads it. Each reader parses one fixed format and does nothing until its key is set.

All of these go in the `today` object unless noted. A path key may start with `~`.

- Task log (top-level key `fleet`, a path): a markdown file where a task is a header `## T-20260101-0900-name  title` and its status is a line appended later: `- T-20260101-0900-name blocked alice 14:05 — waiting on a decision`. The words `claim`, `done` and `blocked` are read. Tasks whose newest status is `blocked` (created within a week) are listed as waiting on you; `done` lines written today are listed as done. A `- T-... done-check PASSED` line marks a done task as checked.
- Plan: `plan_md` is a markdown file whose first heading carries its dates, `# Title (2026-01-05 → 2026-02-05)`, followed by `## Week 1 (01-05 → 01-11): title` sections of `- step` lines (a `- done when: …` line is shown apart). Today shows the current week. `learning_log` is a markdown file of dated lines (`2026-01-06 — what I did`); its newest date is shown as the last session.
- Applications: `applied_csv` is a CSV whose rows start with `YYYY-MM-DD` (then a company and a role); Today shows the newest and the count of the last 7 days. `drafts_dir` is a folder whose files made in the last two days are counted as drafts ready. `jobs_rx` is a regular expression: the newest digest line of today that matches it is shown under the same lane.
- Decision ledger: `ledger_jsonl` is an append-only JSON-lines file; each line is `{"id": "d-1", "status": "open", "title": "…", "opened": "2026-01-02", "lane": "…", "blocks": "…"}`, and the newest line per `id` wins. Each open row is listed oldest first with its age counted from its `opened` day, not a stored age, and flagged when `opened_is_estimate` is true.
- Commitments: `commitments_md` is a markdown list of `- lane | what | how often | proof | source` lines, for example `- Health | Walk 30 minutes | 4/week | check-in`. How often is `daily`, `weekdays`, `N/week`, `every N weeks from YYYY-MM-DD` or `once since YYYY-MM-DD`. The proof is `check-in` (a click on the page, appended to `checkins_jsonl`), `log <file>` (dated lines) or `csv <file>` (dated rows). Nothing is marked kept without a proof. A line starting with `~~` is retired.
- Overnight run: `night_json` is the report of a run that happens while you are away: a JSON file, or a folder of one `YYYY-MM-DD.json` per night of which the newest such name is read and any other name is skipped; its `date` (else the file name's), its counts `ran`, `ready`, `failed`, `refused` (each a number, or a list of items whose length is the count) and its items (`id`, `title`, `repo`, `verdict`, `minutes`) under `items` or those lists; a count the file does not state stays empty, and a report that states no date, or neither a count nor an item, or a date after today is not used. `night_marker` (plain words, any case): when `night_json` gives no report from last night, the newest digest line with these words, a date stamp and a count such as `2 ran`, `1 ready`, `0 failed` or `1 refused` is the report, and the `- ready: …`, `- failed: …` and `- refused: …` lines right under it are its items. Only a report dated today or yesterday is shown; when either key is set and there is none, the page says why in its place.
- Digest lanes (read from the top-level `digest` file): `alert_rx` is a regular expression for digest lines counted as alerts, `fail_rx` for lines counted as failures (default `\bFAILED\b`).

`jobs_rx`, `alert_rx`, `fail_rx` and `night_marker` only filter a digest; on their own they do not turn Today on.

## Sources of your own

These only make sense when the source exists on your machine. Leave them empty otherwise.

- `owner` — string, default `""`. The owner's first name. It is used only to recognise a cited approval in a digest or fleet line (`per <owner>`, `<owner>-approved`, `approved by <owner>`, next to the generic "the owner"), so that line is not parked as a decision.
- `decision_scan` — boolean, default `true`. Find parked decisions from `DECIDE:`, `TODO:`, `FIXME:`, `QUESTION:` lines in text files under the roots (a bounded walk).
- `decision_markers` — list of strings, default `["awaiting decision", "needs a human", "human call", "awaiting owner", "owner's call", "blocked on owner"]`. Phrases (case-insensitive) that make a line in the digest or fleet file count as a parked decision.
- `decision_words` — list of strings, default `["DECIDE:", "TODO:", "FIXME:", "QUESTION:"]`. Words `decision_scan` looks for.
- `quest_priority` — list of `{"label": "...", "match": "<regex>"}`, default `[]`. Orders the board: a line whose text matches an earlier entry sorts before one that matches a later entry or none, and carries that entry's label (at most 12 characters); within the same entry the oldest comes first. Regexes are case-insensitive; an entry with a bad regex is skipped. `[]` runs the board by age alone.
- `digest` — string path, default `""`. A digest markdown file: its lines feed the ticker, parked decisions and the Today screen's "breaks" and jobs lines.
- `fleet` — string path, default `""`. A fleet/intent markdown file of task lines with status (blocked, done); Today's "needs you" / "done" lists come from its blocked and done status lines. A fleet line reaches the parked-decision board only when its text matches one of `decision_markers`.
- `relay_dir` — string path, default `""`. Folder of relay channels, one `<channel>/inbox.md` each; feeds the relay bay and machine evidence.
- `hub_channel` — string, default `"claude"`. Which relay channel the hub reads (`relay_dir/<hub_channel>/inbox.md`). Only `rounds.py` reads it, and that script is not part of the public tree, so setting it there changes nothing; neither example file carries it.
- `reads_jsonl` — string path, default `""`. Digest read receipts (who has read the digest).
- `tags_md` — string path, default `""`. A markdown roots-map table (`| \`root/\` | … | **TAG** | desc |`) that gives each area a tag and description.
- `machines` — object `{machine: [relay names]}`, default `{}`. Relay evidence per machine, e.g. `{"pi-4": ["pi", "claude-pi"]}`. Empty means one node named after `name`. Remote render routes are configured in `seats.json`, not here.
- `tasks_json` — string path, default `""`. The board's audit items (`{"items": [{who, verdict, …}]}`); also read by the self-improve loop and the rounds.
- `rounds_json` — string path, default `""`. The state file the HUD shows as the hub's rounds (keys `started`, `round`, `step`, `step_uid`, `updated`, `last_round_at`, `next_round_at`, `checks`, `verified`, `changes`). `""` means `rounds.json` next to the tool, for the page and for `rounds.py` alike, except with `--root` or in a demo, which have no default. The writer, `rounds.py`, is not part of the public tree: bring your own script that writes that file, or leave this empty.
- `synced_dir` — string path, default `""`. Where other machines' renders arrive (`<machine>/world.json`); `""` means `synced/` next to the tool for the bridge.
- `dispatch_dir` — string path, default `""`. Folder of `d-YYYYMMDD-HHMMSS-<runner>.md` reports; used for the runners hall stats and to link reports to areas.
- `runners_json` — string path, default `""`. The runner registry file shown in the runners hall (the dispatch tool's registry, separate from `runners`).
- `dispatch_bin` — string, default `""`. The dispatch tool the board hands items to; `""` runs `dispatch` from PATH.
- `task_runs_json` — string path, default `""`. JSONL of board items handed to runners (`rid`, `runner`, `out`), used to show status per item; `""` means `.task-runs.jsonl` next to the tool.
- `rulings_json` — string path, default `""`. Your rulings on parked decisions (done / stale); ruled items are retired from the board. `""` means `.quest-rulings.json` next to the tool.
- `audit_json` — string path, default `""`. An auditor's verdict per board item (`{"items": {id: {verdict, recommended, evidence, at}}}`), shown beside the item.
- `today` — object, default `{}`. What the Today screen reads; see [The Today screen](#the-today-screen) below. Only string values (and the `git_dirs` list) are kept.
- `pilot_log` — string path, default `""`. The hub hook's touch log (JSONL: `ts`, `tool`, `uid`) for effort badges and traces.

### Remote T3 metadata

`t3_state` automatically prefers a newer sibling `statev2.sqlite`. Optional `t3_remote`
entries have `machine`, `ssh`, and `path` strings, for example:

```json
"t3_remote": [{"machine": "server-2", "ssh": "server-2", "path": "~/.t3/userdata/statev2.sqlite"}],
```

The bridge refreshes each host in its own background thread every 60 seconds, with a
20 second SSH budget. Only thread metadata, latest run state and lineage are read;
no messages are transferred. Atomic caches live at `ROOT/.container-map/t3-remote/`.
Failures carry their timestamp and error; missing/failed caches never block a render.
Caches older than two minutes stop claiming that agents are working.

Local stores use generic platform labels. A uniquely matching scanned T3 thread supplies its
source machine label; ambiguous matches stay separate. Remote caches retain their configured labels.
